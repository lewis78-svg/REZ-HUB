Lesson 3: Web Security

Welcome to Lesson 3! In this lesson, you will learn how websites work, common web security risks, and how developers can protect websites and users.

1. What Is Web Security?

Web security is the practice of protecting websites, web applications, servers, and users from unauthorized access, data theft, and other online attacks.

2. How Does a Website Work?

  • HTML: Defines the structure and content of a web page.
  • CSS: Controls the appearance and layout of a web page.
  • JavaScript: Adds interactivity and dynamic behaviour.
  • Web server: Delivers website files and processes requests.
  • Database: Stores information used by an application.

3. Common Web Security Risks

a) Cross-Site Scripting (XSS)

XSS occurs when a website handles untrusted content unsafely, allowing harmful scripts to run in another user's browser.

Prevention: Encode untrusted output, sanitize content when appropriate, and use a suitable Content Security Policy.

b) SQL Injection

SQL injection occurs when an application improperly combines untrusted input with database queries.

Prevention: Use parameterized queries, safe database APIs, and least-privilege database accounts.

c) Broken Authentication

Weak login systems or poor session handling can allow unauthorized people to access user accounts.

Prevention: Use strong password storage, multi-factor authentication, secure sessions, and login rate limits.

d) Broken Access Control

This happens when an application allows users to access information or actions they are not authorized to use.

Prevention: Verify permissions on the server for every protected action and resource.

e) Security Misconfiguration

Default passwords, unnecessary services, exposed debug pages, and incorrect server settings can create security weaknesses.

Prevention: Change default credentials, remove unnecessary services, update software, and disable production debugging.

4. What Is HTTPS?

HTTPS uses TLS encryption to help protect data exchanged between a browser and a website. It helps prevent others from reading or changing traffic in transit, but it does not guarantee that a website itself is trustworthy.

5. How to Protect a Website

  • Keep software, frameworks, and plugins updated.
  • Validate input and safely handle untrusted data.
  • Use parameterized database queries.
  • Use HTTPS and secure cookie settings.
  • Apply access controls on the server.
  • Back up important files and test recovery procedures.
  • Monitor logs and investigate suspicious activity.
  • Test only websites and systems you own or have permission to assess.

6. Practical Example

Imagine a school website with a student login page. A secure application checks the student's identity, verifies their permissions on the server, and protects private records from being viewed by other students.

Remember: Hiding a button in the browser is not enough to protect a page. The server must also check authorization.

7. Quick Quiz

Question 1: What is the main purpose of web security?

Show answer

To protect websites, applications, data, and users from security threats.

Question 2: Which technology defines a web page's structure?

Show answer

HTML.

Question 3: What helps prevent SQL injection?

Show answer

Parameterized queries and safe database APIs.

Question 4: Does HTTPS guarantee that a website is honest?

Show answer

No. HTTPS protects communication, but a fraudulent website can also use HTTPS.

Question 5: What must you have before testing another person's website?

Show answer

Permission from the owner.
